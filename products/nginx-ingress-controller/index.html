NGINX Ingress Controller

An Ingress controller with NGINX as its data plane, running in the same pod as the controller. It implements the Ingress API and adds custom resources for the traffic management that Ingress cannot express — and it has the closest annotation coverage to the retired community controller, which makes it the usual destination for a migration.

Apache 2.0 v5.5.4 OSS and NGINX Plus builds
Get Started Documentation GitHub Community

Not the community controller

This is nginx/kubernetes-ingress, built by F5. It is a different project from kubernetes/ingress-nginx, the community controller that has now been retired. If you are moving from that project, the migration tool maps its annotations to their equivalents here.

What it does

Traffic management beyond Ingress

Load balancing, rate limiting, circuit breaking and traffic splitting, through annotations on an Ingress or through the VirtualServer CRD.

Five custom resources

VirtualServer and VirtualServerRoute for routing, Policy for access control and authentication, TransportServer and GlobalConfiguration for L4.

TLS and mTLS

Termination, SSL passthrough, forced redirects, and client certificate validation, with certificates held in Kubernetes Secrets.

TCP, UDP and gRPC

Layer 4 load balancing for workloads that are not HTTP, plus native gRPC and WebSocket support on the HTTP path.

Snippets where you need an escape hatch

Server, location and HTTP snippets inject NGINX configuration directly, so an unusual requirement does not mean forking the controller.

Prometheus and OpenTelemetry

A built-in metrics endpoint and OpenTelemetry tracing, so ingress traffic is visible in the tooling you already run.
